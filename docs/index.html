OpenBO Rust is a library and command-line toolkit for Bayesian, transfer, continual, and multi-objective optimization. Its double-precision CPU runtime needs neither Python nor PyTorch.

Your first experiment

  1. Download the command. Open the latest release, choose the archive for Windows x86-64, Linux x86-64, macOS Apple Silicon, or macOS Intel, verify its accompanying SHA-256, and extract it. The prebuilt command needs no Rust toolchain.
  2. Run a comparison. From the extracted directory, use a terminal: 
    # Linux or macOS
./openbo quickstart

# Windows PowerShell
./openbo.exe quickstart

    Open results/quickstart/comparison.svg. The plot compares random search and BO on Branin with the same 12-evaluation budget. The two JSON files keep every input, observation, and best-so-far value.

  3. Try another seed. Run ./openbo quickstart --seed 1 --output-dir results/seed1 (use ./openbo.exe on Windows). One run is an illustration; compare several seeds before drawing conclusions about an optimizer.

Prefer building from source? Install Rust 1.85 or newer and your platform's linker/build tools, then install the versioned Cargo package:

cargo install openbo-rust --version @PACKAGE_VERSION@ --locked
openbo quickstart

The crates.io package and versioned API documentation retain the release. A Git alternative is cargo install --git https://github.com/M-Colley/openbo-rust.git --tag v@PACKAGE_VERSION@ --locked openbo-rust.

A path through the library

1. Model an unknown function

Fit a Gaussian process and inspect its predictive mean and latent variance. Choose ARD RBF or Matérn-5/2 kernels.

GaussianProcess API

2. Choose the next observation

Score candidates with expected improvement, then explore transfer weights, Pareto geometry, and multi-objective acquisitions.

Acquisition functions

3. Connect your experiment

Use suggest() and observe() to connect an optimizer to your own objective or measurement process.

Ask/tell optimizer API

Clone the repository and run cargo run --release --locked --example student for a complete GP, EI, and ask/tell example. Read the annotated source.

Conventions: every objective is maximized; supplied benchmark inputs lie in [0, 1]^d; GP noise is a variance; predictions describe the latent function. The native evaluation budget is n_init + n_iter.
